# md - a lightweight markdown editor for macOS

Visual sibling to [rahulnkm/stickies](https://github.com/rahulnkm/stickies).
Same frosted-dark palette, same Geist, same hover-reveal chrome - applied to
files on disk instead of floating notes.

## Purpose

Create, edit, and save markdown files. Nothing else.

Files are plain `.md` in a folder the user picks. Any other tool - Obsidian,
Finder, git, an LLM - reads the same files. No database, no proprietary
format, no sync, no account.

Stickies stores notes in its own JSON under Application Support. This is the
opposite: the folder is the source of truth and the app is disposable.

## Non-goals

Search, tags, nested folders, backlinks, sync, export, plugins, images,
floating windows, menu bar item. Each is addable later. None is needed for
"create, edit, save".

## Shape

A native macOS `.app`, one window.

Native was chosen over a browser build because the browser File System
Access API refuses to run from a `file://` page - the spec requires a
non-opaque origin, and `file://` pages have an opaque origin
(https://wicg.github.io/file-system-access/, section 3.1). A browser build
would need a localhost server running permanently. A native app reads and
writes files directly.

## Window

`NavigationSplitView`, sitting on the same frosted-glass background Stickies
uses - `NSVisualEffectView`, material `.hudWindow`, blending
`.behindWindow`, with a dark tint layered on top.

- **Sidebar**, 200pt - every `.md` in the current folder, sorted by name.
- **Detail** - the current file, in one of two modes.

**Edit** is raw markdown in an `NSTextView`, the same wrapper Stickies uses.
It is the only way to modify a file; there is no rich-text surface.
**View** is the same markdown rendered read-only.

## Visual design

Values taken from `NoteTheme` in the Stickies repo, unchanged.

| | |
|---|---|
| Background | `#2C2A33` over `.hudWindow` blur |
| Text | `#E8E3D8` |
| Corner radius | 6 |
| Inner padding | 16 |
| Top padding | 30 |
| Editor font | Geist Mono Regular, 13pt |
| Preview font | Geist Sans Regular, 14pt |
| Line height | 1.0 |
| Tracking | 0 |
| Ligatures | off |

**Tints.** The same four styles - Mist `0.00`, Smoke `0.08`, Slate `0.18`,
Obsidian `0.38` - as the opacity of the dark tint over the blur. Obsidian is
the default here rather than Stickies' Slate: a sticky note is small and sits
over whatever happens to be behind it, but a full window over a bright
desktop needs more tint before body text is comfortable to read.
The tint is a window-level setting here, not per-file: this app is one
window, so a per-file tint would flicker on every selection change. Swatch
lightness values are unchanged: `0.92 / 0.70 / 0.35 / 0.15`.

**Chrome.** Invisible until hovered, exactly as in Stickies: the top strip
is transparent, reveals at 0.9 opacity on hover with a 0.12s ease-in-out,
and uses the same 120ms debounce on hover-out so moving onto a child button
does not flicker. Left side holds the four tint swatches. Right side holds
the Edit/View toggle as a small text button.

**Rendered markdown.** Geist Sans at 14pt with 5pt extra leading. Editing
stays monospaced because column alignment matters while writing markdown;
reading does not need it. Code is the exception and keeps Geist Mono
wherever it appears, a point smaller so it does not tower over the prose
around it.

Stickies bundles GeistMono-Regular only. Three faces are added here under
the same OFL: `GeistMono-SemiBold`, `Geist-Regular`, `Geist-SemiBold`.

- Headings are Geist Sans SemiBold at 24 / 19 / 16 / 14 / 14 / 14pt.
- Bold is SemiBold. Italic is text at `#E8E3D8` with 0.72 opacity, since
  Geist ships no italic face.
- Inline code and code blocks sit on `#E8E3D8` at 0.06 opacity, radius 4.
- Block quotes get a 2pt left rule at 0.3 opacity and 0.75 text opacity.
- Links are `#E8E3D8` underlined; clicking opens the default browser.

**Edit mode.** Markdown syntax characters - `#`, `**`, `` ` ``, `>`, `-` -
dim to 40% opacity so they recede while writing. Everything else is full
strength.

**Sidebar.** Filenames without the `.md` extension, 12pt, 0.75 opacity.
Selected row is `#E8E3D8` at 0.10, radius 4. Unsaved files show the same
`#FEBC2E` stoplight dot Stickies uses for visible notes. Below the name, the
relative modified date at 10pt, 0.45 opacity, via
`RelativeDateTimeFormatter` with `.short` - matching `ManagerView`.

Light mode is not supported. Stickies is dark-only and this matches it.

## Keyboard

| Shortcut | Action |
|---|---|
| `⌘E` | Toggle Edit / View |
| `⌘S` | Save now |
| `⌘N` | New file |
| `⌘O` | Choose folder |
| `⌘⌥←` `⌘⌥→` | Previous / next file |

## Behavior

**Folder selection.** First launch shows an empty state with a "Choose
folder" button. The path is stored in `UserDefaults` and reopened on every
launch. `⌘O` changes it.

Built non-sandboxed, matching Stickies' entitlements. Installed directly
rather than through the App Store, so it needs no entitlement to read an
arbitrary folder and no security-scoped bookmark to remember one.

**Saving.** Autosave 800ms after the last keystroke, matching the debounce
feel of Stickies' `textDidChange`. `⌘S` saves immediately. Switching files
or closing the window saves first. Writes use
`Data.write(to:options: .atomic)` so a crash mid-write cannot truncate a
file.

**New files.** `⌘N` creates `Untitled.md`, then `Untitled (1).md`,
`Untitled (2).md` - the shape Finder uses for copies - and opens it in Edit
mode. On first save, if the body starts with a `# heading`, the file is
renamed to a slug of it. After that first rename the filename is fixed and
never changes on its own.

**Renaming.** Two entry points, one behavior. Right-click a sidebar row and
choose Rename, or double-click the filename in the hover chrome. Both put a
text field in place of the name: Return commits, Escape cancels, clicking
away commits. The rename records which of the two it came from, because
both are bound to the same state and would otherwise each raise a field and
fight over keyboard focus. An explicit name always wins - a file renamed
before its first save no longer takes a name from its heading.

**Show in Finder.** The sidebar's right-click menu reveals the file in
Finder with the file itself selected.

**Soft wrapping.** A lone newline inside a paragraph is a soft wrap, not a
break, and joins - which is what CommonMark does and what makes
hard-wrapped source read as flowing prose. A deliberate break is still
available the two standard ways: end the line with two spaces, or with a
backslash.

**Folder refresh.** The sidebar re-reads the folder when the window becomes
active and after every save. No filesystem watcher - a watcher is a
background process and a source of bugs, and window-focus covers the real
case of editing a file in another app.

**External modification.** Each open file records the modification date it
was read at. On save, if the file on disk is newer, the app does not
overwrite; it shows an inline bar with **Reload** and **Overwrite**.

## Errors

Every one surfaces as a visible inline bar. None fails silently.

| Condition | Response |
|---|---|
| Folder deleted or unreadable | Empty state, offer to choose another |
| Open file deleted externally | Keep buffer, offer **Save as new** |
| File changed on disk | Offer **Reload** / **Overwrite** |
| Save fails | Show the OS error, keep buffer, retry button |
| Not valid UTF-8 | Refuse to open, "Not a text file" |

## Structure

Mirrors the Stickies layout so the two repos read the same.

```
md/
  project.yml                 XcodeGen, matching Stickies' setup
  README.md
  MD/
    MDApp.swift               @main
    AppDelegate.swift         window setup, menu commands
    Info.plist
    MD.entitlements
    Fonts/                    GeistMono Regular + SemiBold, OFL
    Models/
      MDFile.swift            one file: path, body, dirty state, mod date
      Theme.swift             NoteTheme, carried over verbatim
    Storage/
      FolderStore.swift       pick, remember, list, save, conflict detection
    Markdown/
      Blocks.swift            markdown -> block list. No SwiftUI import.
      Inline.swift            inline spans -> NSAttributedString
      MarkdownView.swift      block list -> SwiftUI views
    UI/
      ContentView.swift       split view, hover chrome, error bars
      SidebarView.swift       file list
      EditorView.swift        NSTextView wrapper, adapted from NoteTextView
      BlurView.swift          carried over verbatim
```

`Blocks.swift` and `Inline.swift` are pure - string in, structure out, no
SwiftUI - so they are testable without a UI. `MarkdownView.swift` owns the
one step that needs SwiftUI types, turning spans into `AttributedString`.

## Testing

`xcodebuild test` covers the parser, which is where the logic lives:

- Each block type parses correctly.
- Inline spans within each block type.
- Malformed input - unclosed fence, stray `>`, empty file - does not crash.
- Round-trip: parsing loses no text content.

File I/O is tested against a temp directory: save/load round-trip, atomic
write, conflict detection, slug renaming.

Visual result is verified by hand against Stickies running side by side.

## Build

Same as Stickies. `xcodegen` is already installed.

```
xcodegen generate
open MD.xcodeproj
```

Then `⌘R`.
